# OP Ultra

面向老款小鹏 P7 的 CarPlay 与仪表融合研究项目。

OP Ultra 在 OP CarPlay 的有线／无线连接基础上，接收 iPhone 提供的独立仪表地图，结合车辆实时数据、导航提示与音乐信息，在 P7 仪表上合成宽幅界面。

**适配依据是作者本人车辆的研究和实测：老 P7 E28、骁龙 820A 中控、Android 9。当前研究版本为 0.6.4。其他车辆、系统版本和仪表硬件没有通用兼容性保证。**

项目名称中的 Ultra 用于区分 OP 的仪表融合版本。它不是 Apple 官方 CarPlay Ultra，也不代表获得 Apple 或小鹏的认证、授权或合作。

**仅分享个人研究成果，不接受问题反馈、功能需求或适配请求，不提供安装指导、技术答疑及维护支持。** 开发者可依据项目许可证自行研究和拓展。

## 功能

### CarPlay 与中控显示

| 功能 | 说明 |
| --- | --- |
| 无线 CarPlay | 通过车机 Wi-Fi 与 iPhone 连接，支持复用原车热点 |
| 有线 CarPlay | 支持 USB 连接、手机配对、音视频和拔插后的连接恢复；原车 USB 识别与权限需要先满足条件 |
| 原车分屏 | 支持将 CarPlay 放在分屏区域，原车另一侧应用继续显示 |
| 保留系统栏的全屏 | 根据原车顶部状态栏、底部 Dock 和侧边区域测量实际可用尺寸 |
| 完全全屏 | 隐藏中控系统栏，使用完整画面区域；可设置启动时的默认状态 |
| 触控适配 | 触控坐标随视频显示区域、窗口尺寸与取景关系映射 |
| 中文分类设置 | 左侧分类、右侧设置；仪表设置与车辆读数也在同一设置页 |
| 快捷呼出设置 | 五指张开放下再向内收拢，或三指下滑；支持处理 CarPlay 发来的主机设置请求 |
| 车辆名称与图标 | 可设置 iPhone 中显示的接收端名称及图标 |
| 认证配置 | 保留本地认证文件、自定义认证及相应硬件／远程认证入口，具体条件取决于所选方式 |
| CarPlay 音频 | 保留媒体、导航播报、Siri、通话与麦克风处理；最终路由和体验还受原车音频系统影响 |

普通查看或取消设置通常保留现有连接；改变视频尺寸、认证、连接方式或仪表地图协商参数时，保存后可能需要重新连接。

还保留画面分辨率与帧率、画面尺寸基准、H.264／HEVC 与适用解码选项、音频缓冲、麦克风增益和音量测试、开机自动启动、向 iPhone 提供车机定位，以及连接状态、延迟监测和诊断采集入口。这些属于进阶配置，不代表所有选项组合都在老 P7 上验证通过；中控视频帧率设置也不等于仪表输出帧率。主动麦克风测试会暂时独占麦克风并影响会话。

全屏画面中的小图标用于临时切换是否显示系统栏；启动默认值在设置中选择。「退出应用」结束本次会话和输出，后续启动受用户选择的启动设置及原车系统管理影响。

### 三种仪表输出模式

在「Ultra 仪表 → 仪表投放」中选择，保存后生效。三种模式互斥：

| 模式 | 显示内容 |
| --- | --- |
| Ultra | 1920×720 宽幅合成画面：独立 CarPlay 地图、车速与行程、导航提示及可选信息卡 |
| 仅二路地图 | 将 iPhone 的独立地图送入原车小地图区域，保留原车其余仪表布局；本车已验证请求区域为 660×660 |
| 全部关闭 | 停止 OP 仪表输出，交回原车显示 |

「仅二路地图」不是去掉卡片后的整屏地图。它使用另一条原厂小地图输出路径。切换这两种地图模式可能改变与 iPhone 协商的画布尺寸，因此仍可能重连。

Ultra 的地图是 iPhone 单独提供的第二路视频，**不是截取中控 CarPlay 画面**。中控切到音乐或其他应用后，独立地图仍可继续显示，具体取决于手机地图应用是否持续提供画面。

设置保留地图放大级别，以及投放时隐藏原车车道提示的选项。车道提示与地图是不同图层；停止投放后交回原车，有本轮有效快照时尝试恢复，没有快照时等待原车后续更新，不保证旧车道条立即重现。

### 车速、行程与导航信息

固定信息区域显示：

- 车速及右侧单位。
- 平均能耗，位于车速右侧并右对齐。
- 本次行程距离、行程时间、充电后里程。
- 下一步转向图标、转向距离、转入道路。
- 到目的地的剩余路程、剩余时间和预计到达时间。

转向提示使用独立绘制的箭头，覆盖左右转、直行、斜转、急转、掉头、环岛与到达等已识别类型。已识别方向使用图标表达，不重复显示“左转／掉头”等文字；距离和道路名称保留。未识别的类型使用已有文字或通用提示回退。

导航字段来自 iPhone，不由 OP 自行计算路线。已实现目的地名称解析，但部分手机／地图版本会发回“未知位置”或空值，因此当前主界面使用转向提示，不承诺目的地名称始终可用。

### 信息卡片

可在设置中立即切换当前卡片，或选择下次启动的默认卡片，初始为音乐。固定车速区域与信息卡片可左右互换。

| 卡片 | 内容 |
| --- | --- |
| 音乐 | 专辑封面、上方歌名、下方歌手、播放进度、已播放时长和总时长；内容来自 CarPlay 音乐元数据 |
| 车辆信息 | 四轮胎压、胎温及车辆示意图；门与盖板汇总只在所需信号完整有效时显示 |
| 能耗 | 平均能耗、当前电池功率及当前运行期间的功率变化曲线 |

界面采用半透明卡片、地图背景柔化、左右渐变和上下原车图层融合。外观可跟随原车日夜模式，也可手动指定日间或夜间。

仪表没有触控能力。卡片切换通过中控 OP 设置完成；没有实现仪表触摸切卡，也不把方向盘切歌按键当作卡片切换键。

音乐控制接入原车媒体按键请求机制。本车已确认方向盘「下一首」可使 CarPlay 内歌曲切换；其他按键、播放器、蓝牙组合及重启场景没有全部验证。

### 车辆数据页

设置中的「车辆数据」展示已接入且有效的读数，包括：

- 车速、挡位、电量、WLTP 续航。
- 本次行程、行程时间、充电后里程、总里程。
- 平均能耗、电池功率、空调外温接口读数。
- 四轮胎压和胎温、四门及前机盖状态。
- CarPlay 目的地、剩余路程、剩余时间、预计到达和下一转向距离。
- 歌曲、歌手、播放进度及封面接收状态。

读数保留来源、采集时间与有效期。接口缺失、权限不足、超时、失去连接或数值无效时显示「—」，不会以模拟值填充真实仪表。外温取自原车空调接口，不能保证与原厂仪表显示采用相同的滤波和更新时间。

### 热点、音频与日夜状态

- **可选自动打开原车热点**：默认关闭。开启并完成授权后，在 OP 启动、开机触发或唤醒时检查热点；未开启时尝试调用原车热点功能。复用原车已有的名称、密码和频段，不承诺强制切换为 5GHz。
- **热点就绪等待**：只有本轮由 OP 请求打开的热点，在确认就绪后额外等待约 18 秒，再进入无线连接流程；原本已开启的热点不增加这段等待，有线连接也不受它阻塞。
- **导航播报压低媒体**：检测到导航声道的有效 PCM 时，降低 OP 自身媒体声道音量，播报结束后恢复；不修改整车所有应用音量，不为此额外加入抗抖动缓冲。
- **日夜状态复核**：对前台恢复、原车主题变化和会话状态进行有限复核与同步；隧道场景仍需更多实车验证。

### 授权与恢复

- 在本车已验证的原厂授权服务可用时，可从 OP 设置发起所需的固定授权及车况／仪表服务启动。
- 保留 Shizuku 方式。Shizuku 需要已经运行，并由用户允许 OP 使用。
- 原有本机 ADB／电脑 ADB 入口仍用于适用功能，但它们要求 ADB 已开启并完成对应信任。
- 「有线 CarPlay 授权」准备 OP 的 VPN、麦克风及当前已识别 iPhone 的 USB 访问权限。手机首次信任和 CarPlay 允许仍在 iPhone 上确认。
- 设置提供「开始仪表投放」和停止读取入口；正常关闭投放、关闭全部仪表输出或退出 OP 时执行交还原车显示的流程。

**APK 不等于完整的系统准备工具。** 原车授权服务不可用、Shizuku 未运行或 ADB 已关闭时，不能假定一键授权必然成功。有线授权按钮也不会自动修改 USB 系统过滤规则或刷入框架补丁。

## 使用条件

1. 老 P7 E28／Android 9，并具有与本项目匹配的车况、仪表通道及显示硬件。仅“同为 P7”不足以证明兼容。
2. 车机已有可用的 APK 安装途径。项目不提供通用免初始化安装或通用 ADB 开启方法。
3. 自行准备可用且有权使用的 CarPlay 认证方式。**公开 APK 和源码不包含个人认证证书、私钥或手机配对数据。**
4. 无线连接建议使用原车已配置好的 5GHz 热点，在 OP 中选择原生／手动热点并填写实际 SSID、密码与安全类型。LocalOnlyHotspot 与原生车载热点是不同方式，不能混为一谈。
5. 有线连接须先确认原车能识别 iPhone 数据设备，使用数据线与数据 USB 口，并完成手机及车机提示的授权。USB 系统兼容处理依固件而定，部分现有处理在中控重启后需要恢复。
6. 仪表功能需可用的授权及仪表通信通道。仅二路地图模式还依赖原车当前请求地图卡片；Ultra 宽幅模式则依赖可接管的前景图层。

首次配置可按「认证 → 连接 → 授权 → Ultra 仪表 → 保存／连接」进行。使用中可通过上述手势呼出设置。

## 当前限制

| 项目 | 当前边界 |
| --- | --- |
| 适配范围 | 主要来自作者一辆老 P7 的实测，不是全车型、全固件的通用方案 |
| 官方 Ultra | 未接入 Apple 官方 CarPlay Ultra；车况、卡片和整体仪表布局由 OP 合成 |
| 地图内容 | 地图比例、道路细节、车道级导航、3D、视野和独立屏布局由手机与地图应用决定；与中控画面可以不同 |
| 高德取景 | 只对已识别的高德导航中状态启用特定取景校准；不保证其他手机、地图版本和画布继续适用 |
| 地图附加能力 | 没有独立实现歌词、红绿灯倒计时或额外车道级数据；地图视频本身显示的内容可以随画面透传 |
| 导航字段 | 已实现字段解析不等于每个地图应用都会发送；目的地可能缺失或为占位文本，未知转向也可能回退 |
| 行程时间 | 使用原厂轮转行程数据并做有界缓存；通道中断、数据过期或距离不匹配时仍可能显示「—」 |
| 部分车况 | 尾门接口在本车不完整可用，门盖汇总可能为「—」；车辆示意图并非完整实时开门动画 |
| 帧率 | 仪表输出目标接近 10fps，不是 30／60fps。已有约 50 秒实车样本整体约 9.3fps，预热后部分窗口约 9.3～9.8fps；不代表最终包、所有模式和长期行驶均保持该值 |
| 尺寸切换 | 分屏、系统栏、仪表模式或协商尺寸变化仍可能触发重连，不承诺无缝切换 |
| 锁车与重启 | 原车后台管理、USB 状态、仪表管理通道可能随休眠或重启改变；已出现过通道阻塞，重装 APK 不一定能解决 |
| 自动热点 | 授权、固件和射频状态都会影响效果；完整冷启动、锁车唤醒与长时间使用尚未充分验收 |
| 音频与主题 | 已实现导航降音和日夜复核，但不同 iPhone 的实听效果、通话组合及隧道反复切换尚未覆盖完整 |
| 充电页面 | 已采集充电状态，但未完成按充电状态自动切换／让出整屏的完整逻辑；投放时可能覆盖原车充电画面，可关闭投放恢复 |
| 原车信息与告警 | 保留原车后台显示运行，并对上下信息做图层透出和融合；不等于所有告警、全状态和极端情况下的可见性都已验证 |
| 故障恢复 | 有断流让出、恢复备份和单一输出者交接机制，但不能保证系统强停、掉电或底层通道故障时一定自动恢复 |

车主曾观察到部分 iPhone 在 iOS 27.0.1 出现 CarPlay 桌面第三页打开应用／返回等待，升级至 27.2 后明显改善。这是个别设备现象，不是全部手机的结论，也不意味着已经定位为某条 Apple 修复或由 OP 单独解决。

## 给开发者

实现分为三部分：CarPlay 协议与音视频、Android 车况读取和界面合成、仪表端原生接收与图层恢复。

宽幅模式的主要链路为：

```text
iPhone 独立地图视频 ── 独立解码／取景 ──────┐
原车车况与行程 ─────── 有效期检查 ─────────┤
iAP2 导航与音乐元数据 ── 会话隔离 ─────────┤
                                           ↓
                         Android 1920×720 画布合成
                                           ↓
                         一次 RGB565 转换／LZ4 分块
                                           ↓
                         单帧在途／接收端 ACK／背压
                                           ↓
                         仪表原生接收程序／前景图层
                                           ↓
                         与原厂背景及上下信息融合
```

中控和仪表是两个独立设备。该流程不依赖在仪表上运行 Android APK，也没有把 Kanzi Studio 或 Kanzi 开发运行环境打进 OP；仪表原有程序继续运行，接收端只管理所需的临时显示路径。

详细模块、字段来源、图层处理、权限边界、性能方法和拓展建议见 [开发者技术说明](docs/DEVELOPMENT.md)。
